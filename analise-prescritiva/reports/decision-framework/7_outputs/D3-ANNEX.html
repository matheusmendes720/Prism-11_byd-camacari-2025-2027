Glossário de Termos Técnicos

Todos os termos técnicos mencionados no framework D3 v2.0, organizados por categoria. Inclui termos de game theory adicionados em v2.0.

D.1 — Termos Financeiros e Econômicos
TermoSiglaDefinição
Value at RiskVaRMétrica de risco que estima a perda máxima esperada em um horizonte de tempo (ex: 6 meses) com dado nível de confiança (ex: P95 = 95%). D3 usa VaR 6m P95 em R$.
Conditional VaRCVaRPerda esperada nos piores 5% dos cenários. CVaR 95% = R$ 10.14bi (vs VaR 95% = R$ 8.21bi). Mais conservativo que VaR.
Net Present ValueNPVValor presente líquido. Soma algébrica dos fluxos de caixa futuros descontados a uma taxa (WACC). NPV > 0 = projeto viável. D3 usa WACC 12%.
ViE — Valor de Importação EconômicoViEMétrica de conteúdo local: (custo total do veículo − valor CIF importado) ÷ custo total. Determina elegibilidade a benefícios fiscais (IPI, BNDES). ViE ≥ 18% = Expansão (v2.0 recalibrado).
BNDESBNDESBanco Nacional de Desenvolvimento Econômico e Social. Principal fonte de funding subsidiado para investimentos industriais no Brasil. Funding BYD Camaçari: R$ 800M+ bloqueado por S7 RED.
WACCWACCWeighted Average Cost of Capital. Taxa de desconto usada no NPV. D3 usa 12% para o projeto Camaçari.
IRRIRRInternal Rate of Return. Taxa que zera o NPV. D3 projeta IRR ~26–28% (pré-tariff) caindo para ~14% (pós-tariff 35% sem mitigação).
PTAXPTAXCâmbio oficial de fechamento do Banco Central do Brasil. Calculado diariamente. Usado como reference rate para hedge cambial.
Margin Buffer—Colchão de margem requerido após aplicar hedge. Constraint: VaR residual ≤ 20% da margem bruta.
Break-even—Ponto onde receita = custo (margem = 0). Break-even ViE = 10%: abaixo deste ViE, defensivo destrói margem.
Hedge Ratioh*Percentual da exposição FX que deve ser hedgeada. Otimizado por cenário S3: 30% (Expansão) a 90.6% (RB Total).
Tracking ErrorTEDesvio padrão da diferença entre retorno do portfolio e benchmark. TE = sqrt(E[(R_portfolio - R_benchmark)^2]). Usado para validar previsões D3.

H.1 — Metodologia: Cholesky Decomposition

Problema fundamental: Os 4 fatores de risco (Tariff, FX, Supply, Demand) não são independentes entre si. Para modelar corretamente a distribuição conjunta de perdas, usamos a decomposição de Cholesky da matriz de covariância.

Equação: L = Cholesky(Σ) tal que Σ = L × L^T. Usamos L para gerar vetores aleatórios correlacionados:

Z ~ N(0, I_4)     # 4 variáveis independentes
X = μ + L × Z       # 4 variáveis correlacionadas

Supply  [ +0.20   +0.40    1.00   -0.25 ]
Demand  [ -0.45   -0.30   -0.25    1.00 ]

  • Tariff ↔ Demand: ρ = -0.45 — tarifas mais altas reduzem demanda agregada (elasticidade preço negativa).

I.1 — Metodologia: Tracking Error e Métricas de Acurácia

Framework de validação: Comparamos previsões D3 (output de cada dimensão S1-S11) com outcomes reais observados no período 2020–2025. Cada dimensão recebe um veredicto: VALIDADO (previsão correta), INVALIDADO (previsão incorreta), ou PARCIAL (previsão direção correta mas magnitude errada).

Tracking Error (TE) — Definição:
  TE = sqrt(E[(R_portfolio - R_benchmark)^2])
  Onde R_portfolio = payoff real do cenário
        R_benchmark = payoff previsto pelo D3

  TE expresso em % de market share ou R$ bi dependendo do contexto.

Métricas de Acurácia por Dimensão:

1. Direction Accuracy (DA):
   DA = 1 se (prev_direction == actual_direction) senão 0
   Exemplo: prev=AMBER(+), actual=RED(-) → DA=0

2. Magnitude Accuracy (MA):
   MA = 1 - |prev_value - actual_value| / |actual_value|
   MA = 1 se |erro| < 15%, 0.5 se 15-30%, 0 se > 30%

3. Threshold Accuracy (TA):
   TA = 1 se (prev_status == actual_status) senão 0
   Exemplo: prev=AMBER, actual=AMBER → TA=1

4. Composite Score (CS):
   CS = w1×DA + w2×MA + w3×TA
   Onde w1=0.4, w2=0.3, w3=0.3

5. Tracking Error P95:
   TE_P95 = percentile(95, |prev - actual|)
   TE_P95 < 5% = BOM, 5-15% = ACEITÁVEL, > 15% = RUIM

Período de Validação

  • Train period: 2020–2023 (dados de calibração inicial)
  • Test period: 2023–2025 (dados holdout para validação final)
  • Horizonte: 6 meses (previsão → outcome)
  • Eventos de validação: 23 decisões críticas documentadas

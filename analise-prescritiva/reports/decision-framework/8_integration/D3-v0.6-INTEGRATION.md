## 4. Decision trees v0.6 (era 12, agora escalado para 132)

### 4.1 Estrutura de trees (v0.5)

v0.5 tinha 12 trees = 4 S3 status × 3 S6 status. Cada tree tinha 4 overlays (S1/S2/S4/S5).

### 4.2 Estrutura de trees v0.6

v0.6 mantém os 12 base trees + adiciona 5 overlays (S7/S8/S9/S10/S11) = **12 × 9 overlays = 108 cells** + 24 novas cells (S7/S8/S9/S10/S11 puro) = **132 cells total**.

**Na prática**: para evitar explosão combinatorial, v0.6 usa **rules engine** (YAML) que combina 11 dimensões dinamicamente. Cada cell única vira **state vector** (11-dim) que triggera playbook específico.

### 4.3 State vector exemplo: jul/2026 BYD atual

```
State: {S1: AMBER (78), S2: AMBER (85), S3: GREEN (70), S4: AMBER (72), S5: GREEN (85),
        S6: AMBER (70), S7: RED (92), S8: AMBER (77), S9: GREEN (72), S10: AMBER (78),
        S11: RED (82)}
Composite: ~78 (cluster 2, modo tensão)
```

- Hedge FX: 47% (S1 AMBER + S3 GREEN, constraint binding)

### 9.2 Novas limitações de v0.6

- **L11**: 11 dimensões podem ser excessivas para 1 CSO operar; trade-off entre completude vs operacional
- **L12**: composite weights {s1: 0.18, ..., s11: 0.10} são heurística, não backtested
- **L13**: 132 cells de decision tree é combinatorial explosion; precisa de rules engine
- **L14**: 5 novas personas adicionam 5 camadas de aprovação; pode burocratizar
- **L15**: alguns acoplamentos novos (S7↔S9, S10↔S8) não foram validados com dados empíricos

### 9.3 Caminho C (D3 v2.0) — fecha L11-L15

- L11 resolvida com game theory optimization
- L12 resolvida com backtesting 2020-2025
- L13 resolvida com rules engine + dynamic weighting
- L14 resolvida com auto-trigger (T2.1)
- L15 resolvida com multivariate sensitivity 4 choques
